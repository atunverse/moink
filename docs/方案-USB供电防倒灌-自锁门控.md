# 方案：USB 供电时释放自锁，避免 5V 倒灌电池

> 记录日期：2026-11-11　状态：**已实施（R1.3.6 未发布，待编译 + 真机）**
> 硬件侧：新排线已用 CH213K 反向阻断 + ADC 改接 VSYS 解决，见 §7.1
> 关联：`PIN_SELF_LOCK=2`（CONTRACT §2）、电池 ADC `GPIO0`（CONTRACT §2 / §7）

## 1. 背景：FPC 免飞线供电板

自研 FPC 柔性板，让 ESP32-C3 SUPERMINI 免飞线装配。板上有：

| 部件 | 作用 |
|---|---|
| 电池管理芯片（充电 + 保护） | 电池侧充放电管理 |
| 两个 **AO3401 背靠背** P-MOS | 电池 ↔ 开发板 5V(VBUS) 脚的**双向通断开关**（真断开，不靠体二极管） |
| 栅极由 GPIO2 驱动 | GPIO2 **高 = MOS 导通 = 电池给板子供电**（一键开机自锁） |

固件侧对应行为（现状）：

- `app_main()` 第一条语句就 `gpio_set_level(GPIO2, 1)` —— 拉高自锁，松手不断电（`main.c:1149`）。
- 深睡时 `gpio_hold_en(GPIO2)` + `gpio_deep_sleep_hold_en()` 锁存高电平维持供电（`power.c:119`）。
- 关机动作 `power_self_lock_off()` 把 GPIO2 拉低断电（`power.c:137`）。

## 2. 故障机理：5V 从 VSYS 倒灌进电池

```
        ┌──── USB 5V (VBUS) ──────────┐
        │                             ↓
        │                    开发板 5V 脚 (VSYS) ──→ LDO ──→ 3V3 ──→ MCU
        │                             ↑
  电池 ── 电池管理芯片 ── AO3401 ═══ AO3401 ──┘
                              ↑
                       栅极 ← GPIO2（高=导通）
```

**背靠背的用意是"双向真断开"，但只要栅极常通，它就退化成一根导线。**
USB 插入时 5V 出现在 VSYS；自锁把电池也接到 VSYS ⇒ **5V 直接压在电池/管理芯片 BAT 脚上**。

压差 = 5.0 − 3.9 ≈ 1.1 V，回路阻抗（电池内阻 ~0.1 Ω + 两管 Rds(on) ~0.12 Ω + 走线）≈ 0.25 Ω
⇒ **倒灌电流 3~4 A**，且**没有 CC/CV 限制**（走的是 MOS，不经过充电管理）。
后果：电池过压/大电流充电（发热、鼓包）、管理芯片 BAT 脚反向灌流。

> ⚠️ 这是**安全项**，不是体验项。优先级高于任何功能排期。
> ⚠️ 现有"背靠背"设计本身没有失效——失效的是"栅极被固件永久拉高"这个用法。

## 3. 为什么不能"运行时检测 USB 插入"

| 手段 | 能否用 | 原因 |
|---|---|---|
| ESP32-C3 片内 VBUS 检测 | ❌ | C3 的 USB-Serial-JTAG **不提供 VBUS 状态位**，只能感知 D+/D- 上的主机活动 |
| `usb_serial_jtag_is_connected()` | ⚠️ 仅辅助 | 只对**电脑/USB 主机**有效；接充电头（D+/D- 悬空）**完全测不到** |
| 充电芯片 STAT 脚 | ❌ | 硬件未接到 MCU；且满电后 STAT 变高阻，本来就不可靠 |
| 温度/功耗特征 | ❌ | 延迟大、个体差异大，不可判 |

**但真正的突破口是：我们不需要"检测 USB"，只需要"检测 VSYS 上有没有超出电池范围的电压"。**
5 V 和 4.0~4.2 V 本来就能用现成的电池 ADC 分开——只要分压点能看到 VSYS。

## 4. 核心判据

> **V_adc > 4.6 V ⇒ 外部 5 V 存在（USB 插入）⇒ 立刻释放自锁。**
> **V_adc ≤ 4.6 V ⇒ 只有电池 ⇒ 正常自锁。**

- 4.6 V 高于单节锂电物理上限（4.2 V + 余量），也低于 5 V，中间有 0.4 V 滞回空间。
- 与"充电是否进行"无关：本次用的是**电压台阶**，不是充电电流特征 ⇒ 满电、慢充、涓流都能判出。
- 现有 `power_battery_mv()` 的 `BAT_MV_MAX 4600` 会把 5 V 过滤成 `-1`（判"未连接"），
  所以**不能直接用**，需新写一个不做量程过滤的原始读数函数。

## 4.1 已确认的硬件事实（2026-11-11）

| # | 事实 | 影响 |
|---|---|---|
| 1 | 自锁栅极**有下拉电阻** | 上电瞬间 AO3401 天然关断 ⇒ **零倒灌采样窗口存在** ✔ |
| 2 | 电池 ADC 抽头在 **MOS 之前（电池侧）** | MOS 断开时读到的是电池本体，**看不见 VSYS 上的 5 V** ⇒ §4 的判据失效 ✘ |

### 由此得到的死锁

    要看见 5 V  → 必须导通 MOS → 一导通就倒灌
    不要倒灌    → 必须保持断开 → 只看得见电池电压

抽头位置不改，**任何靠电压采样的策略**都绕不开这个循环。出路有三条：

1. **不看电压，看按键**（方案 A″，纯软件，现在就能落地）
2. **把抽头挪到 VSYS 侧**（方案 A′，下一版改板，最优雅）
3. **短脉冲"先导通再看"**（方案 B，有倒灌代价）

## 5. 可行路线（按落地时机排序）

### 方案 A″（现在就能落地，零改板）：用「按键自证」判断上电方式

**物理前提**：按键与 AO3401 并接在主通路上，**电池能到达 VSYS 的唯一路径就是"按键按住"**。

**自证逻辑**（这是它比电压检测更硬的地方）：

    按键松开 → MOS 未导通 → 电池断开 → MCU 立刻失电
    ⇒ 能跑到 app_main 且按键已松开，必然存在另一路电源（USB）

也就是说，**不存在"电池上电但读不到按键"的情况**——那种情况设备根本活不到判断的那一刻。
所以判据不会误判（不会把电池误判成 USB 而意外掉电），只会"开机失败"（用户按太短）。

固件逻辑：

    读 GPIO5（先 pullup + input，等 ~100 µs）
      低 → 按键按住 → 电池开机 → 拉高 GPIO2 自锁
      高 → 按键松开 → USB 上电 → 不拉高，不自锁

**必须一起做的三个分支**（漏掉会掉电或倒灌）：

| 分支 | 判据 | 动作 |
|---|---|---|
| 真冷启动 | `esp_reset_reason()` = `ESP_RST_POWERON` / `ESP_RST_EXT` | 走上面的按键判据 |
| 运行中复位（软件重启 / 看门狗 / OTA） | 其他 `ESP_RST_*` | **直接自锁**，不看按键（设备本来就是开着的） |
| 深睡唤醒 | `ESP_RST_DEEPSLEEP` | **不要碰 GPIO2**（hold 已锁存），只做 USB 轮询 |

> ⚠️ 漏掉第二行会出事：页面「保存并重启」、OTA 重启、WDT 复位时按键是松的，
> 会被判成 USB → 不自锁 → 电池供电下直接掉电。

**风险与代价**：

- **按键必须按到 `app_main` 才有效**（约 150~250 ms 的 boot 时间）。按短了就是"按了没反应"，
  需要产品说明写"按住约 0.5 秒开机"。
- **不覆盖"运行中才插 USB"** —— 那条没有上电过程，只能靠 200 ms ADC 轮询
  （MOS 导通时电池节点被灌到 5 V；1M‖1M + 100 nF 的 τ ≈ 50 ms，200 ms = 4τ，读得到）。
  两个机制互补，合起来覆盖全部场景。
- **不覆盖"插着 USB 同时按键"** —— 按键低会被判成电池 → 自锁 → 倒灌；
  但 200 ms 轮询随后会发现 5 V 并释放，属可接受的最坏情况。


### 方案 A′（推荐）：抽头改到 VSYS 侧 —— 一根线，不是加元件

把分压电阻的上端从「电池节点」改接到「VSYS 节点」（开发板 5V 脚 / MOS 之后）。

判据立刻变成三态：

| MOS 状态 | 供电来源 | ADC 读数 | 动作 |
|---|---|---|---|
| 断开（上电瞬间） | 按键开机 | 3.7~4.2 V（按键把电池接到 VSYS） | 自锁 ✔ |
| 断开（上电瞬间） | USB | 5.0 V | **不自锁** ✔ |
| 导通（运行中） | 电池 | ≈ 电池电压 | 正常 |
| 导通（运行中） | USB | 5.0 V | 200 ms 内释放自锁 ✔ |

**关键：这不损失电池电压测量精度。** 电池供电时 MOS 导通，
`VSYS = Vbat − Rds(on)×I`（60 mΩ × 80 mA ≈ 5 mV），对电量显示毫无影响；
而 MOS 断开时本来也不需要测电池。

⇒ 零倒灌、一次判定，顺带白送一个「是否 USB 供电」的状态位。

### 方案 B（抽头不动时的退路）：10 ms 试探脉冲 + 差值判据

1. MOS 断开时读 `V0`（电池本体）。
2. 拉高 GPIO2 导通，延时约 **10 ms**，读 `V1`。
3. `V1 − V0 > 150 mV` 或 `V1 > 4.55 V` ⇒ USB 在 ⇒ 立即拉低并**锁存**"不自锁"。
4. 否则保持自锁。

- 判据用**差值**而不是绝对值：无 USB 时导通只会因负载把电压拉低几 mV（差值为负），不会误判。
- 代价：**每次电池开机给电芯来一发 ~10 ms 的 3~4 A 无 CC 充电**（约 15~30 mAs）。
  单次能量与容量影响都很小，但"每次开机都来一下"长期不优雅，
  且可能在电池保护板 OVP（4.25~4.3 V）边缘反复触发。
- **上限取决于分压网络有没有 100 nF**：1M‖1M 配 100 nF ⇒ τ ≈ 50 ms，
  10 ms 只能看到目标跳变的 ~18%（约 180 mV），刚好够用；
  若电容更大或读数噪声更大，就得拉长脉冲、倒灌同步变长。

### 方案 C：`usb_serial_jtag_is_connected()` 当辅助
只在"插电脑"时成立，可作为额外信号（插电脑 = 一定要防倒灌），**不能当主判据**。

### 方案 A″ 的场景判定（2026-11-11 逐条过）

| 场景 | 判定 | 说明 |
|---|---|---|
| 无按键插 5V 自动上电 | ✅ 不自锁 | 读 GPIO5 高 |
| 5V 供电下自动休眠 | ✅ 继续保持不自锁 | 进深睡时 hold **当前电平（低）**，不是无条件 hold 高 |
| 5V 一直插着 | ✅ 保持 | — |
| 5V 一直插着后拔掉 | ✅ 直接掉电，接受 | 深睡上下文丢失，下次插/按键都走冷启动判据 |
| 插着 5V 唤醒 | ✅ 读到 hold 低 ⇒ 判定 USB | ⚠️ 但插 USB 本身**不产生唤醒源**，只有按键 / 定时器能唤醒 |
| 按键开机（无 5V） | ✅ 自锁 | 读 GPIO5 低 |
| 电池状态「关机」 | ✅ 拉低 → 断电 → 回到冷启动 | — |
| 电池状态「休眠」 | ✅ hold 高；唤醒读 hold 高 ⇒ 判定电池 | — |
| **电池休眠中才插 5V** | ❌ **纯软件无解**（见下） | 需 light sleep 或改硬件 |

### 深睡期间插 USB：为什么 ADC 心跳不可行

**结论：ESP32-C3 深睡中做不了 ADC 采样。** 这不是配置问题，是硬件能力问题。

| 尝试 | 为什么不成立 |
|---|---|
| ULP 协处理器里跑 ADC | C3 的 ULP-RISC-V 只能访问 RTC 域外设；SAR ADC 挂在 APB 域，ULP 无权限。只有 ESP32 初代的 ULP 带 ADC 指令 |
| 定时唤醒 + 采样 | 每次唤醒都要重走 bootloader（~200 ms）。压到"倒灌可接受"的 1 s 周期 ⇒ 平均电流几 mA，电池几天耗尽；放到 10 min ⇒ 倒灌 10 min ≈ 3 A 野蛮充电，比不检测好不了多少 |
| GPIO 高电平唤醒 | 阈值固定 ≈ 0.55×VDD ≈ 1.8 V，**不能设成 4.6 V 对应的 2.3 V**；电池 4.0 V 分压后已 2.0 V，会持续误唤醒 |

**能做到的**：进深睡**前**判一次。此时 MOS 仍导通，插着 USB 的话电池节点已被灌到 5 V，
200 ms 轮询早就发现了 ⇒「插着 USB 去休眠」能正确处理。

**做不到的**：电池供电进入深睡**之后**才插 USB。GPIO2 被 hold 高，5 V 直接倒灌，
而芯片睡着了没有能力发现它。三条出路：

1. **说明书约束**：休眠中别插充电线，要充先唤醒（零成本，靠人）
2. **改 light sleep**：C3 light sleep ≈ 300 µA，可 1 s 周期醒来跑 ADC（倒灌 ≤ 1 s），
   代价是待机从 5 µA（年级）降到 ~400 µA（约 200 天）
3. **下一版硬件根治**：VSYS 感知自动断流 / 理想二极管，与固件无关

## 6. 无法用软件消除的两个残余

1. **按键开机 + USB 同时在场**：典型一键开关机电路里按键与 MOS **并接在主通路**上，
   按下瞬间电池与 VSYS 直通 ⇒ 硬件层就倒灌了，固件没有任何插手余地。
   （只能靠"别在插着 USB 时按键开机"的操作习惯，或硬件加二极管。）
2. **拔 USB 即断电**（见方案 A 代价），要"无缝续接"只能改硬件。

## 7.1 新排线已把问题在硬件上解决（2026-11-11）

用户重做了 FPC，两处改动：

1. **背靠背里的一只 AO3401 换成 CH213K 理想二极管**做反向阻断 ⇒ 即使自锁导通，
   VSYS 的 5 V 也进不了电池。
2. **ADC 分压上端改接 VSYS**（原接电池侧）⇒ 任何时刻都能直接读到 5 V。

充电仍走独立的 **4057**（VSYS → 电池），不受反向阻断影响。

### 但固件分不出新老排线

| 状态 | 老排线 ADC | 新排线 ADC | 可区分 |
|---|---|---|---|
| 电池供电、已自锁 | 电池 3.0~4.2 V | 电池 3.0~4.2 V（VSYS≈电池） | ✘ |
| USB、已自锁 | 5.0 V（正在倒灌） | 5.0 V（VSYS） | ✘ |
| USB、**未自锁** | 电池 3.0~4.2 V | **5.0 V** | ✓ |

只有第三行有差异，而「未自锁」本身是保护逻辑的产物 —— 鸡生蛋。电池开机时两版读数
完全一样。所以**只能手动选**，不能开机自动识别。

（理论上可做「插着 USB → 释放自锁 → 读一次」的主动自检，差异 1.3 V 很好判；
  用户决定不做，改为在页面上手动勾选。）

### 最终定案

| 项 | 做法 |
|---|---|
| 冷启动 | **只认按键**：按下 ⇒ 自锁；已松 ⇒ 判 USB、不自锁。**不读电压**（不猜板型） |
| 运行中 | 仅自锁态 200 ms 轮询，**连续 3 次**（600 ms）> **4500 mV** ⇒ 释放自锁 |
| USB 开机 | 本就不自锁，电池已隔离 ⇒ **不轮询** |
| 新排线 | `gpio_preset=排线 && line_v=1` ⇒ **轮询整段跳过**（CH213K 已阻断，ADC 接 VSYS 会误判） |
| 深睡 | 按当前状态锁电平，USB 态锁「低」 |
| 休眠门控 | `gpio_preset=排线 && line_v=0` 且已自锁 ⇒ 强制走关机；`line_v=1` 允许休眠 |

**冷启动为什么砍掉电压判据**：刷机后用户还没选接法，固件既不知道用哪个唤醒脚、也不知道
分压接在哪一侧。此时若拿电压当判据，猜错就等于主动自锁倒灌。统一只按按键判，
「没配置」这个状态本身就不会倒灌 —— 代价只是接法选错时电池开不了机（插 USB 进页面改）。

阈值 **4.5 V**：满电 4.2 V 留 0.3 V 余量，覆盖 4.6~4.8 V 的劣质电源；电池带载
3.9~4.1 V 顶不到。设置项 `line_v` 默认 **0（老排线）** —— 误判成新排线会真倒灌，
反向误判只是少睡一觉。

**新排线为什么必须跳过轮询**：它的 ADC 接 VSYS，插着 USB 时读到 5 V。若照样轮询，
刚插上线 600 ms 就把自锁释放掉 ⇒ 电池被隔离 ⇒ 拔线瞬间断电。跳过之后，插线保持自锁、
电池在下面兜着，拔线不断电。（CH213K 已保证这时不会倒灌，轮询对它没有意义。）

## 8. 若决定改硬件（根治，需 1~3 个元件）

> 新排线已按第 3 条思路（理想二极管）实现，本节留作老排线的改造参考。

按代价从低到高：

1. **串一只肖特基**（SS14 / 1N5819）在"电池 → VSYS"路径：倒灌彻底堵死，压降 0.25~0.3 V，
   电池可用下限抬高；软件零改动。
2. **把栅极门控改成 VSYS 感知**（1 个 PNP/NPN + 2 个电阻）：VSYS 被抬高时**自动**关断 MOS，
   纯硬件、无需固件参与、拔 USB 也能续上电池 ⇒ 体验最好。
3. **真理想二极管**（LM66100 / AO3401 + 比较器）：压降 ~30 mV，最干净，成本最高。

## 11. 状态记忆：复位后如何恢复自锁态（方案 A″ 的第四分支）

「运行中复位 → 直接自锁」这条规则有一个反例：**USB 供电下的软件重启**
（页面「保存并重启」、OTA 重启）。这时按键是松的，若无条件自锁就会倒灌。

正确做法：用 `RTC_DATA_ATTR` 变量记住自锁意图，复位后按记忆恢复：

```c
RTC_DATA_ATTR static uint32_t s_lock_magic;
RTC_DATA_ATTR static uint8_t  s_lock_want;   /* 1=自锁(电池)，0=不自锁(USB) */

if (s_lock_magic != 0x4D4F494E) {            /* 冷启动 / 首次上电 */
    走按键判据;
} else if (esp_reset_reason() == ESP_RST_DEEPSLEEP) {
    不动 GPIO2;                               /* hold 已锁存 */
} else {
    按 s_lock_want 恢复;                      /* 软件复位 / WDT / OTA */
}
s_lock_magic = 0x4D4F494E;
```

- RTC 域在深睡与软件复位中都不掉电，只有真断电（拔电池/USB）才丢 ⇒ 魔数正好区分冷启动。
- 每次自锁状态变化时同步更新 `s_lock_want`。
- 唤醒 / 复位后若要改变 GPIO2，必须先 `gpio_hold_dis()`，否则 `gpio_set_level()` 无效。
