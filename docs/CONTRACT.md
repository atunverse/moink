# 墨印 · MoInk — 传输与驱动契约（CONTRACT）

> 本文档是**固件与页面之间的唯一权威接口定义**，以及**屏驱动的物理契约**。
> 改动任何一条必须同步更新 `check_frame.py` / `smoke_page.js` 并全量回归。
> 版本：api = 2，fw = R1.1.1，page = R1.1.1。

---

## 1. 帧格式 v1 / v2（`POST /api/frame`）

整帧上传，**无局部刷新**。请求体 = 16 字节头（大端）+ 2bpp 载荷。

| 偏移 | 长度 | 字段 | 值 |
|---|---|---|---|
| 0–1 | 2 | 魔数 | `0xA5 0x5A` |
| 2 | 1 | 格式版本 | `1` = 768×552 载荷 / `2` = A1 原生 800×600 载荷（api 2 起） |
| 3 | 1 | 面板类型 | `0`=A0 / `1`=A1（**仅信息性**，实际面板由设备设置决定，不随帧切换） |
| 4–5 | 2 | 宽（大端） | `768`（v1）/ `800`（v2） |
| 6–7 | 2 | 高（大端） | `552`（v1）/ `600`（v2） |
| 8–11 | 4 | 载荷长度（大端） | `105984`（v1）/ `120000`（v2） |
| 12–13 | 2 | CRC16（大端） | CRC-16/CCITT-FALSE，仅对载荷字节计算 |
| 14–15 | 2 | 保留 | `0` |

- 载荷：`宽/4 × 高` 字节的 **2bpp** 位图——768×552 → `105984`；800×600 → `120000`。
- **几何接受规则**（`epd_frame_geom_ok()`）：A0 / A1.1 只接受自身画像尺寸；**A1 两种几何都接受**
  （768×552 给 a1_mode 3/4 与旧页面热更未跟进时，800×600 给 a1_mode 1/2）。
- CRC 算法：**CRC-16/CCITT-FALSE** — poly `0x1021`，init `0xFFFF`，无反射、无终异或（非 CCITT/IBM 反射变体）。黄金测试向量：`"123456789"` → `0x29B1`。
- 校验顺序：魔数 → 版本 → 宽高 → 载荷长度 → 流式收载荷并累加 CRC → CRC 比对。任一失败返回 `400`；缓冲被占用（上一帧正在刷）返回 `500 busy`。

## 2. 2bpp 位图编码

- 每字节 4 像素，**MSB 优先**：像素 `x` 位于字节内位 `(6 - 2*(x%4))`。
- 色码（A0 实测，与部分参考实现相反）：
  | 2bit 值 | 颜色 |
  |---|---|
  | `00` | 黑 K |
  | `01` | 白 W |
  | `10` | 黄 Y |
  | `11` | 红 R |
- 纯色整屏字节值：黑 `0x00`、白 `0x55`、黄 `0xAA`、红 `0xFF`。

## 3. 180° 几何契约（缓冲 ↔ 逻辑图）

缓冲与逻辑图像呈 **180° 旋转**关系（页面在浏览器里合成时已按此契约打包，固件只原样写屏）：

- 缓冲第 `r` 行 = 逻辑图像第 `y = H-1-r` 行（**自下而上**存储）。
- 每行内像素从左到右仍按 `x` 升序填充，但字节内 2bit 组序也倒（见 §2 的位映射）。
- 逻辑图 `(0,0)`（左上角）落在缓冲**最后一个字节的低 2 bit**。

页面的 `packIdx()` 与固件 `epd_display_2bpp()` 必须严格对应；`check_frame.py` 的 180° 放置断言即是此契约的黄金校验。

## 4. 屏画像：A0 / A1 / A1.1

### 4.1 玻璃与栅极布线（2026-09-22 定案，FB-009/FB-010 取证）

- 三种拆机屏（A0 批次、A1 批次、A1.1 批次）**可见区同为 768×552**，外观一致。
- **A1 批次的栅极按两 bank 交错布线**（卖家可用固件映射 + 真机症状共同证实）：

  | 可见行 i | 驱动它的栅极 y |
  |---|---|
  | 0 … 299 | 偶数栅极 `2i`（0,2,…,598） |
  | 300 … 551 | 奇数栅极 `2i−599`（1,3,…,503） |

  其余奇数栅极 505..599 未接可见行（备用）。**因此源行必须交错送进栅极**：顺序写入会让
  画面的偶/奇行分别落进上下半屏 —— 表现为上下半屏穿插、纵向条纹、中部割裂（FB-009 现象）。
- **行内变换**：A1 批次源线顺序与 A0 相反 → **行内不做变换即正向**；套用 A0 的整行镜像会得到
  左右镜像（FB-010 现象）。A1.1 沿用 A0 的行内镜像语义。

### 4.2 A1 四档驱动模式（`a1_mode`，仅 A1 生效，默认 3）

| a1_mode | 名称 | 帧几何 | TRES / 窗口 | 行 → 栅极 | 写入方式 |
|---|---|---|---|---|---|
| `1` | 方案A 原生·顺序 | 800×600 | 800×600 | `y = i` | 一个整窗 + 单次 0x10 |
| `2` | 方案A′ 原生·交错 | 800×600 | 800×600 | `y = 2i / 2i−599` | 一个整窗 + 单次 0x10 |
| `3` | **方案D 相位1（默认）** | 768×552 | 768×600 | `y = 2i / 2i−599` | 逐行单行窗 + 0x10 |
| `4` | 方案D 相位2 | 768×552 | 768×600 | `y = 2i+1 / 2i−598` | 逐行单行窗 + 0x10 |

- 档 1/2 按控制器原生 800×600 渲染；本屏可见区 768×552，故这两档会**按可见区裁切**
  （右 32 列 / 下 48 行落进备用源线与备用栅极），保留作对照诊断。
- 档 3/4 是 1:1 正解：768×552 帧经交错映射恰好覆盖 552 条可见栅极，零重采样、无白边。

### 4.3 画像表

| 项 | A0 | A1 | A1.1 |
|---|---|---|---|
| 枚举值 | `0` | `1` | `2` |
| 帧几何 | 768×552 | `a1_mode` 1/2 → 800×600；3/4 → 768×552 | 768×552 |
| Y 映射 | **隔行半屏**：`j < H/2 ? j*2 : 2*(H-j)-1`（`lower_y_base = -1`） | 见 4.2 | 整窗线性（`lower_y_base = 0`） |
| 行内变换 | 整行镜像（缓冲 180° 契约的逆） | **不变换**（勾「左右镜像」才叠加镜像） | 整行镜像 |
| 初始化 | 标准 A0 路径 | JD79665 式（0xAA 解锁 + 0x65/0x84 级联），BUSY 窗口 180s | 同 A1 |
| 验证状态 | ✅ 已上机 | ⚠️ R1.1.0 四档待真机逐档确认 | ⚠️ 诊断画像 |

- 面板切换**运行时生效，无需重刷**，且**不能随帧切换**（帧头 hdr[3] 仅信息性）。
- 显示名：`epd_panel_name()` 返回 `"A0"` / `"A1"` / `"A1.1"`。
- 帧缓冲静态分配按最大合法载荷 `800/4 × 600 = 120000` 字节（`EPD_MAX_BUF_LEN`）。

## 6. HTTP API 路由（`api = 2`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 控制页（web 分区优先，否则内嵌页） |
| GET | `/api/info` | 状态 JSON：fw/page/api/panel/**a1_mode**/heap/bat_mv/sleep_s/wake_s/clients/ssid/uptime |
| GET | `/api/settings` | 读设置 JSON：panel/hflip/a11_var/**a1_mode**/wifi_pwr/sleep_s/wake_s/ssid/pass_set |
| POST | `/api/settings` | 写设置（`panel`/`hflip`/`a11_var`/`a1_mode`/`sleep_s`/`wake_s`，`ssid`+`pass` 成对） |
| POST | `/api/frame` | 传图（§1 帧格式） |
| POST | `/api/ota` | 固件升级（写另一槽 + 切换 + 45s 确认）；可选查询参数 `?sync_page=1` = 校验通过后一并清除页面热更标记，改用内嵌新页面（R1.1.1，FB-012） |

## 7. 设置与 NVS

- 命名空间 `moink`；键 `panel` / `hflip` / `sleep_s` / `wake_s` / `ap_ssid` / `ap_pass`。
- 休眠档位（`sleep_s`）：`0`=不休眠 / `60` / `180`（默认）/ `300` 秒。
- 定时唤醒档位（`wake_s`）：`0`=关（默认）/ `3600` / `43200` / `86400` 秒。
- 热点：SSID 空 → 默认 `MoInk-XXXX`（XXXX = MAC 后 2 字节）；密码空 → **开放**。AP 通道 1，最多 4 客户端，DHCP DNS 指向 `192.168.4.1`。
- 页面自身所有画面参数（风格 / 强度 / 文字 / 旋转 / 方向）一律存于手机 `localStorage`（key `moink.cfg4`，历史键自动一次性迁移），**固件不存、不回读**。

## 8. 版本判定流程

- 固件接口 `api` 不变时，页面升级**只走 `/api/web`**，无需重刷固件。
- 页面改动若触碰 §1–§6 任一契约，则 `api` 需 +1，并强制重刷固件。
- 回归门禁（必须全绿）：
  - `python tools/check_frame.py`（帧契约黄金校验）
  - `node tools/smoke_page.js`（页面纯函数 + 帧头 + 旋转 + 文字层几何）
  - `python tools/check_algo.py`（算法冻结，12 函数逐字 MATCH）

> **★ 算法基线 B2（2026-09-22，FB-002 Stage A）**：用户授权解锁后重立。quantize 允许
> 「std 标准档」注入块（CDEC 分通道 decode γ1.75 + 黄 (255,230,0) / 红 (220,0,0) 目标色），
> check_algo 剥离该块后与 M7 冻结版逐字比对；其余 11 函数仍逐字 MATCH。
> std 档参数为真机定稿值（`samples/FB-002/校准表-StageA-final.md`），linear/sRGB 两旧档行为不变。
