# 00 · 开始读这里

这是**四色墨水屏（黑/白/红/黄）照片转换工具**的完整任务交接包。
目标是让一台陌生电脑上的 AI 拿到本包后，不需要追问就能理解项目、继续开发或复用其方法。

> 包内所有原作者本机的绝对路径（`C:\Users\...`）已清洗为占位符或包内相对路径，
> 解压到任意目录都可直接使用。文末「路径约定」一节说明了需要替换什么。

---

## 一、一句话说明

这块墨水屏物理上**只能混合出红→橙→黄**这一小段色相（RGB 空间里 R 为最大通道、
B 为最小通道的那一块），蓝、青、绿**在任何抖动比例下都混不出来**，必然塌缩成黑或白。
所以冷色调照片直出就是一张黑白抖动图。

解决办法是**在抖动之前**把色彩信息映射进暖色带，而不是在后端抢救。

实测（768×552，红+黄像素占比，其余为黑+白）：

| 照片 | 不做处理（对照） | 自然暖调 | 全面暖色映射 |
|---|---|---|---|
| 冷调·海滩 `samples/p7.jpg` | 0.2 % | 0.8 % | 34.1 % |
| 暖调·米色织物 `samples/q19.jpg` | 9.0 % | 19.1 % | 33.4 % |

## 五、验证：怎么证明改动没弄坏

进入 `project/` 目录，按顺序：

```bash
python gen_test.py          # 生成 Python 参考输出 → xcheck/
node verify_vs_js.mjs       # 跨语言逐像素比对 → 要求 0 索引差异
python test_e2e.py          # 无头浏览器端到端 → 要求 0 控制台错误
python check_exports.py     # 用 PIL 独立解码导出文件并互相比对
python test_edge.py         # 边界：无图导出、非 4 倍数宽度、细缝裁剪
python make_demo.py         # 重新生成效果样张
```

**判定标准**（重要，别只看跑没跑完）：

- `verify_vs_js.mjs`：四色索引输出**必须 0 像素差异**。浮点最大差 < 1e-9 属 V8 与 numpy
  末位舍入（典型 ~6.8e-13）。**真正的逻辑错误会差 1/255 ≈ 0.004 量级**——量级能直接区分
  「舍入」和「写错了」。
- `test_e2e.py`：0 个控制台错误 / pageerror。
- `check_exports.py`：各格式解码后像素统计一致，且只含 4 种调色板颜色。

当前基线：**21 组参数用例 × 4 种抖动算法，0 像素差异**。改动后若低于此即为回归。

## 六、三个改之前必须知道的约定

1. **`eink_warm.py` 是算法唯一真源**，`eink-warm-converter.html` 里的 JS 是它的逐行移植。
   改任何一侧，**另一侧必须同步**，并跑完上面第五节。两侧各有一处常量必须一致：`WARM_SAT_K`（默认 0.75）。
2. **饱和度提升必须用幂律** `s → s^(1 − 0.75·g)`，**不要改回「向满饱和线性靠拢」**。
   线性方案会把 s=0.18 的米色织物推到 ~0.66，整张照片糊成一片红，直接违背「保留原照片观感」的需求。
3. **色相偏移两项必须按亲和度加权混合**，不要写成 `if (hd > 60)` 硬切换。
   硬切换会在接缝处产生 3–5° 跳变（画质上表现为渐变出现等值线），
   且结果会由 1e-16 的浮点差决定，导致两侧语言对不齐。

## 七、路径约定

- 包内 `<PY>` = 你的 Python 解释器路径；`<NODE>` = 你的 node 可执行文件路径。
- `01-项目说明.md` 第 6 节的命令已替换成 `<PY>/python.exe` `<NODE>/node.exe`，按你的环境替换即可。
- `project/make_demo.py` 依赖 **Windows 系统字体**（`C:/Windows/Fonts/msyh.ttc` 等）。
  在 macOS / Linux 上跑请把第 31–32 行的字体候选改成该系统存在的中文字体路径；
  它只用于生成对比样张，不影响主工具与其余测试。
- 其余脚本均使用 `__file__` 推导路径，解压到任何位置都能跑。

## 八、接手建议：按目的选路线

| 你的目的 | 怎么做 |
|---|---|
| 只想用这个工具 | 浏览器打开 `project/eink-warm-converter.html`，什么都不用装 |
| 微调效果（更艳/更淡、换屏尺寸） | 读 `01-项目说明.md` 第 3、4 节；改界面滑杆即可，通常不必动代码 |
| 改色彩算法 | 先读 `04` 理解需求演进，再读 `02`；**双侧同步**后跑第五节全套 |
| 加功能 / 改界面 | 读 `01` 第 5 节改动规则；跑 `test_e2e.py` 与 `test_edge.py` |
| 换一块别的调色板的屏 | 读 `02`，按第一节方法**先算清目标色域的凸包**，不要凭感觉猜 |
| 做另一个「单文件网页 + 非平凡算法」的工具 | 直接复用 `03` 的方法论与 `03b/03c` 脚本骨架 |

**最容易踩的坑**：看到「冷调照片处理后红黄只有 0.8%」以为是失败。
这是**设计要求**——用户明确要求「不要把整张图都变成红黄，原本偏蓝的区域不必强行改成橙红」。
想要极致暖色，切到「全面暖色映射」模式即可。详见 `04`。
