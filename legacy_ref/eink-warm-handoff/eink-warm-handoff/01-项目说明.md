# eink-warm —— 四色墨水屏（黑/白/红/黄）照片转换工具

**目标设备**：华为 nova14 墨水屏手机壳 A0 屏，**768×552，3.98 寸**。工具打开即为此尺寸。

**主交付物**：`eink-warm-converter.html` —— 单文件离线网页，双击用浏览器打开即可，
Windows / macOS / Linux / Android 通吃，无需安装、无需联网、照片不出本机。

---

## 1. 这份工具解决什么问题

4 色墨水屏每个像素只能显示黑、白、红、黄之一。这四色在 RGB 空间能"平均"出来的
颜色，色相全部落在 **0°~60°（红→橙→黄）**——即 R 为最大通道、B 为最小通道的那一块区域。
**蓝、青、绿在物理上无法被混合出来**，抖动时只能就近还原成黑或白。

所以一张冷色调照片直接丢给四色屏，结果就是一张黑白抖动图。实测（768×552）：

| 照片 | 原图直出（不处理） | 自然暖调 | 全面暖色映射 |
|---|---|---|---|
| 冷调·海滩 `samples/p7.jpg` | 0.2% | 0.8% | 34.1% |
| 暖调·米色织物 `samples/q19.jpg` | 9.0% | 19.1% | 33.4% |

（数字为红+黄像素占比，其余为黑+白。）

关键动作是**在抖动之前**把色彩信息映射进暖色带，而不是在后端抢救。

## 3. 色彩模式（下拉框）

| 模式 | 行为 | 何时用 |
|---|---|---|
| `natural` 自然暖调（**默认**） | 只提亮本来就偏暖的色调，冷色保持中性 | 绝大多数照片 |
| `adaptive` 全面暖色映射 | 整幅压进红黄带，红黄用量最大 | 想要极致暖色效果 |
| `sunset` / `ember` / `duotone` / `sepia` | 按亮度套用预设暖色渐变（LUT 风格） | 风格化 |
| `gray` 纯黑白 | 不做色彩映射 | 对照 |
| `naive` 原图直出 | 不做任何色转，直接四色抖动 | 对照（复现"只剩黑白"的问题现场） |

### 自然暖调的两个核心设计

**① 色相亲和度 `warmAffinity(hue)`**
落在红橙黄带（350°~360°、0°~60°）给 1 分，向两侧各 50° 用 smoothstep 平滑衰减到 0。
冷色相**不被拽进暖色带**，只做有上限的漂移 + 部分去饱和；黄绿（草叶）落在坡道上只被轻推。

**② 饱和度用幂律提升 `s → s^(1 − WARM_SAT_K · g)`，`WARM_SAT_K = 0.75`**
（g = warmBoost × 亲和度）

**这里不要改回"向满饱和线性靠拢"**：那会把 s=0.18 的米色毯子直接推到接近纯红，
照片失去自身观感。幂律单调、0→0、1→1，能保住暖色之间的饱和度比例——含蓄的仍然含蓄。
实测暖色像素饱和度中位数 0.15 → 0.28，线性方案会到 0.66（照片糊成一片红）。

## 4. 主要功能

- **导入**：拖拽 / Ctrl+V 粘贴 / 点击选择 / 手机直接拍照
- **裁剪 / 旋转**：左右旋转 90°；裁剪框可拖动、四角缩放、点空白重新框选；
  比例支持 自由 / 屏幕比例 / 1:1 / 4:3 / 3:4 / 3:2 / 16:9
- **缩放方式**：裁满全屏 / 完整放入（留白边）/ 拉伸变形
- **一键优化**：先量"不加强时能出多少红黄"再决定推多用力（>14% 用 0.35，>5% 用 0.55，否则 0.75）
- **实时统计**：黑/白/红/黄占比 + 红黄利用率判定
- **1:1 查看**：按屏幕实际像素核对抖动网点
- **示例照片**：内置一张，打开就能看到效果

### 导出格式

| 按钮 | 说明 |
|---|---|
| PNG（四色抖动） | 通用 RGB PNG，任何看图软件/上位机都能开 |
| 四色索引 PNG | 2bit 调色板 PNG，体积最小（约 67KB vs 237KB），颜色绝不会被重算 |
| BMP | 24bit，给只认 BMP 的驱动 |
| RAW 2bpp | 每像素 2bit，索引顺序可在高级参数切换（黑/白/红/黄 或 黑/白/黄/红） |
| **连续调彩图（未抖动）** | 已做色彩处理但**没抖动**，传给自带抖动功能的软件可避免二次抖动 |
| **仅抖动图（无色转）** | 只抖成四色、不做色彩转换 |
| 复制图片 | 复制到剪贴板 |

> 若刷出来仍是黑白，多半是厂家上位机自己又做了一次二值化 —— 改用「四色索引 PNG」或「RAW 2bpp」。
> RAW 的索引顺序请对照屏幕数据手册。

## 5. 改动规则（重要）

1. **`eink_warm.py` 是算法唯一真源**，`eink-warm-converter.html` 里的 JS 是逐行移植。
   任何一侧改动，另一侧必须同步，**并跑一遍第 6 节的验证流程**。
2. 两侧各有一处常量必须一致：`WARM_SAT_K`（暖色饱和幂律强度，默认 0.75）。
3. 色相偏移两项必须按 `warmAffinity` 加权**混合**，不要写回 `if (hd > 60)` 硬切换。
4. CSS 里必须保留 `[hidden]{display:none !important}`：否则 `.two{display:grid}` 这类
   作者样式会盖掉 UA 的 `[hidden]` 规则，`el.hidden = true` 静默失效。
5. JS 里 `window.__eink` 暴露了内部函数供测试调用，不要删（测试脚本依赖它）。

## 6. 验证流程（改完按顺序跑）

```bash
PY="<PY>/python.exe"
NODE="<NODE>/node.exe"

$PY gen_test.py                     # 生成 Python 参考输出到 xcheck/
$NODE verify_vs_js.mjs              # 跨语言逐像素比对 → 要求 0 索引差异
$PY test_e2e.py                     # 浏览器端到端 → 要求 0 控制台错误
$PY check_exports.py                # 独立解码六种导出并互相比对
$PY test_edge.py                    # 边界：无图导出、非 4 倍数宽度、细缝裁剪
$PY check_exports.py odd-750x502    # 校验非 4 倍数宽度的导出
$PY make_demo.py                    # 重新生成效果对比样张
```

**判定标准**

- `verify_vs_js.mjs`：量化输出（四色索引）**必须 0 像素差异**；浮点最大差 < 1e-9 视为
  V8 与 numpy 末位舍入（典型值 ~6.8e-13）。**真错了会差 1/255 ≈ 0.004 量级。**
- `test_e2e.py`：0 个控制台错误 / pageerror。
- `check_exports.py`：六种格式解码后像素统计一致，仅含 4 种调色板颜色。

## 7. 回归清单：这些坑已经踩过，别再踩

| 坑 | 症状 | 教训 |
|---|---|---|
| 阶段顺序被调换（先提饱和 vs 先混合渐变） | 默认值用例 100% 通过，saturation=1.9 时偏差 59 | 两阶段在参数中性值处可交换，**只有非默认参数用例抓得到** |
| 色相 60°/350° 硬切换 | 1e-16 的浮点差让纯黄像素落到阈值两侧，输出差 15/255 | 接缝处用加权混合；同时也是画质问题（渐变出现等值线） |
| `[hidden]` 被作者样式覆盖 | 别的模式的参数一直露在界面上 | 加 `!important`，测试断言 `getComputedStyle` |
| 索引 PNG 用未压缩 deflate | 两张不同的照片导出**同样 106633 字节** | 文件大小与内容无关 = 编码器没压缩。改用 `CompressionStream('deflate')` |
| 尺寸滑杆 `step=8` | 所有可达宽度都是 4 的倍数 | 手工 2bpp 打包器的"末字节半填"路径根本走不到，改为 step=1 |
| 重构时丢分支 | `dither(mode="none")` 静默失效 | 交叉验证里保留每个模式的独立用例 |

## 8. 已知边界

- `WARM_SAT_K`(0.75) 与默认 `warmBoost`(0.60) 是目视 + 统计定的。若觉得偏保守或偏艳，
  改 `warmBoost` 即可（界面滑杆）；要改曲线形状才动 `WARM_SAT_K`，且两侧必须同步。
- 纯冷色照片（天空、雪、水面）在自然暖调下**本就该保持中性灰**——这是设计要求，不是缺陷。
  想要天空也有颜色，调高「冷色偏移」或切「全面暖色映射」。
