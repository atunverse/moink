# Cross-language numerics: failure modes and observed magnitudes

Concrete case: a 4-colour e-ink image pipeline (Python/numpy reference, vanilla JS port
inside a single-file HTML tool). Three real bugs and their signatures.

## Observed signature table

| cause | symptom | magnitude |
|---|---|---|
| missing final clamp on one branch | exact-match share drops to ~60%, output indices still ~100% match | float delta up to 16 |
| lookup keyed off a different stage (pre- vs post-transform luminance) | every test case fails, exact-match share ~30% | float delta ~1e2 |
| dropped branch during a refactor (`dither("none")`) | one mode only, indices differ | 0 float delta, ~17% index mismatch |
| two stages swapped in the port | the case with the neutral parameter value is **100% exact**, its sibling is 0% exact | float delta ~59, index mismatch ~40% |
| hard `if` at a branch boundary with a different formula on each side | 70–85% of samples exact, the rest off by a lot, all clustered at one input value | float delta 15–60 |
| V8 vs libm last-bit rounding | exact-match share 70–85%, **indices 100%** | float delta ~5e-13 |

The last row is the important calibration point: a genuine logic error produces deltas on
the order of a quantisation step (1/255 ≈ 0.004 or larger), while a last-bit difference sits
around 1e-13 relative to a 0–255 scale. Set the gate at `max_delta < 1e-9` **and**
`index_mismatch == 0`. Both are needed — a dropped branch shows zero float delta but breaks
the quantised output.

## Two bugs that defaults-only tests cannot see

**Swapped stage order.** The reference applied `blend toward the ramp` and then
`chroma gain`; the rewritten port applied `chroma gain` and then `blend`. At gain 1.0 the
gain stage is a no-op and the two are bit-identical — so `adaptive_default` passed at 100%
while `adaptive_tuned` (same mode, gain 1.9) came out 0.059% exact with a float delta of 59
and a chroma of 55% vs the reference's 65%. Fix: match the documented order, and comment the
order wherever two stages commute at neutral settings.

**A hard branch switch at a seam.** The mapping did
`if (hue > 60) pull toward 60 else pull toward warmCentre`. The two branches shift hue by
differently-shaped amounts, so at `hue == 60` there was a 3.6° jump (and 4.8° at the other
seam at 350°). A pure-yellow pixel therefore had the two implementations land on opposite
sides of `60.0` because of a ~1e-16 difference in `hue`, and the outputs differed by 15/255.
Only 265 of 19200 pixels (all yellow-green) were affected — a signature you would dismiss as
noise if you only looked at the percentage.

The fix is not to widen a tolerance. Replace the switch with a blend weighted by the same
smooth function that already drives the rest of the stage:

```js
/* before: discontinuous at hd = 60 and hd = 350 */
h2 = (hd > 60 && hd < 350) ? coolBranch(hd) : warmBranch(hd);

/* after: both terms present everywhere, weight w is continuous in hd */
var drift = clamp(-coolPull * (1 - w) * (hd - 60), -coolCap, 0);
var pull  = clamp(warmPull * shortestAngle(warmCentre - hd), -warmPullCap, warmPullCap);
var h2    = mod(hd + drift + w * pull, 360);
```

This is worth doing even without a port to verify: a discontinuity in a smooth gradient
prints as a contour line, and it makes the output depend on the last bit of a float, so
future refactors will find new "disagreements" forever.

## Module semantics that silently differ

Python's float `%` is `a - floor(a/n)*n`, so the result always has the sign of `n`:

```python
-1e-17 % 1.0   # -> 1.0
```
```js
(-1e-17 % 1 + 1) % 1   // -> 0.0   (the naive port)
((a % n) + n) % n      // -> 1.0   (correct port)
```

Rounding:

```python
np.round(0.5)   # 0.0   banker's rounding
np.round(1.5)   # 2.0
```
```js
Math.round(0.5) // 1.0   half away from zero
Math.floor(x + 0.5)     // use this on both sides
```

`numpy.interp` uses the slope form; an algebraically equal rearrangement changes the last bit:

```python
slope = (y1 - y0) / (x1 - x0); out = slope * (x - x0) + y0
```

`np.max` / `Math.max` on a 3-element axis agree exactly for finite inputs, so either is fine —
do not spend time on it. The same applies to `np.maximum(d, 1e-12)` vs `Math.max(d, 1e-12)`
when the value is already above the epsilon.

## Buffers and iteration

Iterate a flat interleaved float64 buffer on both sides. The numpy version may use `(H,W,3)`
arrays for the vectorised tone/colour stages and a `.reshape(-1).tolist()` flat loop for the
sequential error-diffusion stage; the JS version uses one flat `Float64Array` throughout. As
long as the arithmetic per element is identical, the outputs are identical — but the
*sequential* stage (error diffusion, IIR filters, any pixel that reads already-modified
neighbours) must iterate in exactly the same order, including the same serpentine direction
per row. Row parity and neighbour offset order are part of the spec.

## What to test

- every mode and every branch of the dither/filter selector
- both extremes of every numeric slider, plus the default
- **every branch at its own non-neutral parameter values** — the case that catches a swapped
  stage order is the one where the parameter that makes the two orders differ is not at its
  identity value (gain ≠ 1, angle ≠ 0, mix ≠ 0)
- toggles on and off (auto-levels, invert, sharpen = 0 and > 0)
- input pixels that are exactly 0 and exactly 255 (clamp boundaries)
- pixels with no chroma (r=g=b) so hue is undefined and any tie-break shows up
- pixels whose hue lands **exactly on a branch threshold** (0, 60, 350 …) — this is what
  turns a latent discontinuity into a failing case
- pixels where two channels tie for max, to pin the tie-break order
- a non-square image and a size that is not a multiple of the byte/word packing unit
- a synthetic input that sweeps the whole domain (a hue wheel plus a neutral ramp plus the
  palette colours plus noise) rather than a photograph: photos exercise the common path and
  hide the boundary cases

## Pre-flight checklist before declaring a port verified

1. The script is extracted from the **shipped artefact**, not a copy under `src/`.
2. Every reference output is stored as raw binary, compared as raw binary.
3. The gate is `max_delta < 1e-9` **and** `quantised_mismatch == 0`.
4. A deliberate perturbation of the JS makes the harness fail (prove it can detect bugs).
5. The same reference files, regenerated from the reference implementation, still pass —
   i.e. the reference itself did not drift.
