# Imaging for tiny-palette displays

## Start by computing what the palette can actually reach

Do not guess. Take the palette as RGB points and work out the convex hull's hue range.

For **black / white / red / yellow** the reachable set is every colour where
**R is the max channel and B is the min channel** — hue 0°~60° (red→orange→yellow) only.
Blue, cyan and green **cannot be averaged** from these four, at any dither ratio. Those
pixels will always collapse to black or white no matter how good the dither is.

Practical consequence, measured on a 768×552 cold-toned beach photo:

| stage | red+yellow share |
|---|---|
| naive 4-colour dither of the original | **0.2 %** |
| after mapping into the warm band | 34–43 % |

This is the whole problem. Everything below is about how much of the photo you are willing
to move.

## Pick a strategy, and offer the user both

| strategy | what it does | when |
|---|---|---|
| **selective** (`natural`) | hues that are *already* warm get more vivid; cool hues are **not** dragged into the band, only nudged and partly desaturated | default — keeps the photo looking like itself |
| **global** (`adaptive`) | compresses the entire hue circle into the warm band | the user explicitly wants maximum red/yellow, or the photo is almost entirely cool |
| **control** (`naive`) | no colour transform at all, just dither | always ship this — it reproduces the user's complaint and proves the fix works |

Ship the control mode. It turns an argument about taste into a side-by-side number.

## The two pieces of the selective model

**1. Hue affinity — a smooth weighting, never a threshold.**

```python
def warm_affinity(hdeg):            # for a black/white/red/yellow panel
    # 1 inside the reachable band (340..360, 0..60), smoothstep down to 0
    # across the 50-60 deg on either side (violet/magenta, yellow-green).
    t_hi = clip((hdeg - 300) / 60, 0, 1)
    t_lo = clip((hdeg - 60) / 60, 0, 1)
    w = where(hdeg > 300, t_hi*t_hi*(3-2*t_hi),
              where(hdeg < 120, 1 - t_lo*t_lo*(3-2*t_lo), 0.0))
    return where((hdeg <= 60) | (hdeg >= 340), 1.0, w)
```

**Blend the two hue-shift terms by this weight** (`h + (1-w)*drift + w*pull`). Do not write
`if h > 60:` — a hard switch puts a 3–5° discontinuity at the seam, which shows up as a
contour line across smooth gradients *and* makes the result depend on which side of the
threshold a last-bit float difference lands on.

**2. Saturation must use a power law, not a linear approach to full saturation.**

```python
s2 = s ** (1 - K * g)      # K ~ 0.75, g = boost * affinity
```

This is the single most important calibration in the whole pipeline, and the obvious
choices are both wrong:

| curve | what happens to a muted warm tone (s=0.18, beige fabric, pale skin) |
|---|---|
| `s + (1-s)*k` (linear → full sat) | pushed to ~0.66 — **the whole photo turns into flat red blocks** |
| `s * (1+k)` (multiplicative) | too timid on sunsets and skin, barely any colour appears |
| `s ** (1 - K*g)` (power law) | 0.15 → 0.28, muted stays muted, vivid becomes vivid ✅ |

The power law is monotonic, maps 0→0 and 1→1, and crucially **preserves the ordering and
the ratio between two warm colours** — so the picture keeps its own character.

## Pipeline order

1. resize to the panel (cover / contain / stretch — let the user choose)
2. exposure: auto-levels (percentile clip ~0.5%), brightness, contrast, gamma
3. **colour transform** ← the part above; must happen *before* dithering
4. luma unsharp (~0.3) — sharpen on luma only, it makes dither texture read as detail
5. error diffusion (Floyd–Steinberg, strength ~0.85; Atkinson is cleaner, Bayer 8×8 has no
   worm artefacts, "none" is useful as a reference)
6. export

## Evaluating: histogram the output, do not eyeball it

Count the share of each palette entry. Report **red+yellow vs black+white** as the headline
number, and treat these as the sanity gates:

- a cold photo under the selective model should stay *low* on red+yellow — that is correct
  behaviour, not a failure. Do not flag it as a warning.
- a warm photo should roughly double its red+yellow share versus the naive control.
- if two different photos export to the **same file size**, the encoder is not compressing.

## Export formats, and the double-dither trap

- **RGB PNG** — universally accepted, but any downstream tool may re-quantise it.
- **indexed PNG (2bpp, 4-entry palette)** — smallest, and the palette is declared so
  nothing downstream can reinterpret the colours. Preferred for vendor flashing tools.
- **BMP 24bit** — for drivers that only accept BMP.
- **RAW 2bpp** — for microcontrollers writing straight to a framebuffer. Index order
  (KWRY vs KWYR) differs per panel; make it switchable and tell the user to check the
  datasheet.
- **continuous-tone (un-dithered) colour image** — for software that does its own dithering;
  feeding it an already-dithered image causes visible double-dither.
- **dither-only (no colour transform)** — the control output.

**If the panel still shows black and white:** the vendor's PC software is almost certainly
re-binarising the image. Switch to indexed PNG or RAW, which bypass the re-quantisation.
