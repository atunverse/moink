墨印 MoInk 一键刷机包
版本：R1.2.0（固件与控制页共用同一个版本号；2026-09-24，api 保持 2）
================================================

本版三件事：
  ① 版本号合并 —— 不再有「固件版本 / 页面版本」两套，界面上只显示一个「版本」
  ② 升级入口合并 —— 只有「① 升级」一个上传口，固件和控制页都能传，
                    设备按文件内容自动识别，你不需要判断这次升的是哪一种
  ③ 升级强制重置 —— 刷固件会重置设备设置（热点名与密码保留下来，不会失联），
                    顺带清掉 A1.1 测试变体等过时的旧代码

文件夹内容（放在同一个目录）：
  MoInk一键刷机.bat        双击运行（没装 Python 会引导自动安装）
  flash_on_pc.py           刷机脚本（bat 自动调用，也可命令行单独运行）
  moink_R1.2.0_merged.bin  固件整包（0x0 写入，含 bootloader + 分区表 + 固件）
  moink_R1.2.0_app.bin     OTA 升级包（设备已能开机时，在网页里上传）
  page-R1.2.0.html         创作页面（网页里「① 升级」上传，免刷机）
  test_frame_post.py       诊断工具（PC 直连发四色测试帧，验证显示链路）

怎么升到本版
------------------------------------------------
【推荐】方式 A：设备现在跑 R1.1.x，网页里直接升
  1. 控制页「设置 → 系统维护与升级」，把 moink_R1.2.0_app.bin 选进去
     （R1.1.x 的旧页面上这个按钮叫「① 固件」，点它上传即可）
  2. 等设备重启完成（约 1 分钟）
  3. 重启后页面自动变成新版（控制页随固件一并更新），版本显示 R1.2.0

方式 B：需要整包刷写 / 首次使用
  1. 双击 MoInk一键刷机.bat。如果这台电脑没有 Python，
     会询问「是否自动下载并安装」，输入 y 回车即可。
  2. 用【数据线】（能传数据的，不是纯充电线）把板子接到电脑 USB 口。
  3. 双击 MoInk一键刷机.bat，等它自动选串口、自动刷写（约 1~2 分钟）。
     脚本只认带 VID 的真实 USB 串口，蓝牙等虚拟串口（无 VID）会自动跳过。
  4. 看到 [OK] 刷机完成即可。手机 Wi-Fi 连 MoInk-XXXX（默认开放）→
     浏览器打开 http://192.168.4.1

※ 方式 B 会整体覆盖设备上的现有固件与设置。

★ 网页里升级只需选文件，不用判断类型
------------------------------------------------
本版起只有一个升级入口：
  · 传 moink_R1.2.0_app.bin（.bin）→ 固件升级：写备用分区 → 校验 → 切槽
    → 顺带更新控制页 → 重置设备设置（热点名与密码保留）→ 自动重启
  · 传 page-R1.2.0.html（.html）→ 只热更控制页：CRC32 校验 → 替换
    → 不重启，刷新浏览器即可
设备按文件**内容**识别（固件首字节 0xE9 / 页面以 <!doctype 或 <html 开头），
不看后缀名，也不看浏览器报的类型。

注意事项
------------------------------------------------
- 不要用浏览器网页烧录器！本板是 C3 原生 USB-JTAG（VID 0x303a），
  网页烧录器（WebSerial）会卡死在 "Stub running..."，一个字节都写不进。
- 如果卡死或失败：拔插一次 USB，然后在本目录打开命令行运行：
      python flash_on_pc.py --no-stub
- 查看本机全部串口：
      python flash_on_pc.py --list

刷完验证（四项）
------------------------------------------------
1. 控制页「设置」设备状态应显示：版本 R1.2.0 / 接口 2
   （不再有「固件」「页面」两行）。
2. 传一张图，屏幕应在约 15~25 秒内完成刷新。

□ V1 统一入口·固件：只上传 moink_R1.2.0_app.bin → 设备重启，版本显示 R1.2.0，
   设置回到默认，而**热点名与密码保持不变**。

□ V2 统一入口·控制页：只上传 page-R1.2.0.html → **不重启**，
   刷新浏览器页面即生效，版本显示 R1.2.0。

□ V3 A1 屏驱动（FB-013 一并验收）：
   适用 A1 批次屏。控制页「设置」→「屏幕设置」→「屏幕」选 A1
   →「A1 驱动」下拉只剩两档，默认是「768×552 顺序」。
   用【非对称测试图】上传（推荐 samples/FB-010/测试图片/01_非对称方向图.png，
   图上带文字 + 箭头 + 四角编号），默认档下逐项检查：
     □ 满屏无裁切 —— ★最关键，右侧与底部没有内容被切掉
     □ 四角编号齐全
     □ 方向正确 —— 文字可读、不左右反、不上下倒
     □ 无白边
     □ 无穿插条纹
   切到「方案A 原生800×600」能看到右 32 列 / 下 48 行被裁 —— 那是对照档的
   预期行为，不是故障。

□ V4 强制重置生效：升级前把「A1 驱动」切到「方案A 原生800×600」、把休眠档
   改掉；升级后应回到「768×552 顺序」与默认休眠档，而热点名 / 密码仍是
   升级前设的值。

※ 关于「左右镜像」勾选框：A1 的默认档「768×552 顺序」行内变换是固定正向的，
  这个勾选框对默认档不再生效（保留给对照档与 A0 屏）。

本版主要更新（相对 fw R1.1.1 + page R1.1.1）
------------------------------------------------
- ★ 版本号合并：固件与控制页共用同一个版本号，界面只显示一个「版本」。
- ★ 升级入口合并：固件与控制页走同一个「① 升级」入口，按内容自动识别。
- ★ 升级强制重置：刷固件重置设备设置（热点名 / 密码保留）。
- ★ A1 驱动收敛为「768×552 顺序直写」（R1.1.3 内容并入）：帧几何 = 玻璃
  可见区 768×552，栅极顺序写入，1:1 铺满，不裁切、不重采样、无白边。
- ★ 设置保存就地反馈 + 保存后回读核对（R1.1.3 内容并入）：成功 / 失败 /
  「没收到应答」全都看得见，不再"点了保存像没反应"。
- 删除过时代码：A1.1 测试变体、A1 交错相位档、固件内置页的逃生开关等。
- api 保持 2：帧格式、色彩、几何规格（768x552 / 800x600）均无变化。

旧固件 / 旧页面的不兼容说明（重要）
------------------------------------------------
- R1.1.x 的固件里**没有** /api/upload 这条路由。如果你把 page-R1.2.0.html
  热更到一台还是 R1.1.x 固件的设备上，再去点升级，页面会提示
  「设备固件过旧，不含统一升级入口」—— 这是预期行为，请先按方式 A / B
  把固件升到 R1.2.0。
- 反过来，R1.2.0 固件里**没有** /api/ota 与 /api/web 了：R1.1.x 的旧页面
  也无法升级本版设备。请使用本包里的页面。
- 升级会重置设备设置（A1 档位 / 左右镜像 / 休眠 / 唤醒 / 发射功率 / 屏幕类型），
  **热点名与密码保留**。页面侧的画面参数（风格 / 强度 / 文字 / 旋转）存在
  手机浏览器里，不受影响。
- 恢复内置页面按钮仍在（设置页「① 升级」下方），用于把热更的控制页清掉、
  回到固件内置的那一份。
